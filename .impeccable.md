## Design Context

### Users
The creator uses Pi Bot as a local IM to send real work to persistent bots, read results, manage bot schedules and monitors, and view or take over each bot's Linux desktop.

### Brand Personality
Simple, calm, personable. Bots should feel like individual contacts with expressive avatars; the UI should stay quiet during long work.

### Aesthetic Direction
The creator explicitly chose the installed Grok Bot as the reference. Warm cream messenger aligned with the approved asymmetric coral pi logo; compact contact list, peach outgoing bubbles, centered conversation identity, overlay details with read-only routines and computer. No Ant Design, Chatscope, or AI chatbot dashboard.

### Design Principles
- Reuse Radix controls and existing Pi SDK contracts.
- Keep real message history intact and distinguish delivery from reading or task completion.
- Move operational detail into the bot's details panel.
- Use bounded motion for feedback, and respect reduced motion.
- Keep navigation, composer, and long content usable in narrow windows.

- Desktop navigation resizes into an avatar rail; one mixed bot/group list and one Cmd+K search.
- Routine execution is direct. Only genuine decisions use a question card; errors belong to the affected message, with safe recovery backed by host evidence.
